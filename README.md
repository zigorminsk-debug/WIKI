# Локальная база знаний Confluence

Оффлайн-first приложение для **Android** и **Windows**. Оно хранит страницы Confluence в локальной SQLite-базе, позволяет искать и читать их без сети, а затем синхронизирует кэш с Confluence REST API. Один код Flutter собирается в APK и Windows EXE.

## Что уже реализовано

- Настройка адреса Confluence (IP или DNS-имя), логина и пароля в приложении.
- Basic Auth к Confluence Server/Data Center REST API (`/rest/api/content`).
- Загрузка всех доступных текущих страниц, включая HTML-тело, пространство, иерархию и номер версии.
- Локальная SQLite-база и поиск по заголовку, пространству, пути и тексту страницы.
- Просмотр сохранённой страницы без подключения к серверу.
- Ручная синхронизация и автоматическая синхронизация раз в 24 часа:
  - Android: фоновая периодическая задача при доступной сети;
  - Windows: проверка при запуске и таймер, пока приложение открыто.
- Пароль находится только в защищённом хранилище ОС (`flutter_secure_storage`), а не в SQLite, настройках или журнале.
- GitHub Actions собирает installable APK и portable Windows EXE-пакет после каждого push.

> **Важно.** Фоновая задача Android запускается системой с допустимой задержкой (это ограничение Android/WorkManager), а не в точную минуту. Windows-приложение не устанавливает скрытую системную службу: синхронизация идёт при запуске и пока оно работает.

## Настройка Confluence

1. Откройте вкладку **Настройки**.
2. Укажите базовый адрес, например `https://192.168.1.20:8443/confluence` или `http://10.0.0.15`.
   Не добавляйте `/rest/api/content` — приложение добавит путь само.
3. Введите логин и пароль учётной записи Confluence, у которой есть право просмотра нужных пространств.
4. Нажмите **Сохранить и синхронизировать**.

Поддерживается REST API Confluence **Server/Data Center**. Для Confluence Cloud вместо пароля обычно требуется API token; его можно указать в поле «Пароль». Для production рекомендуется HTTPS с сертификатом, доверенным устройством. Поддержка `http://` включена только потому, что IP-адреса во внутренних сетях часто используют HTTP.

## Локальная разработка

Нужен Flutter stable c Android SDK для APK и Windows development tools для EXE.

Репозиторий намеренно не хранит сгенерированные платформенные каталоги. После клонирования один раз выполните:

```bash
flutter create --platforms=android,windows --project-name confluence_kb --org ru.zigorminsk .
python tool/configure_platforms.py
flutter pub get
```

Далее:

```bash
flutter test
flutter analyze
flutter run -d windows
flutter build apk --release
flutter build windows --release
```

APK появится в `build/app/outputs/flutter-apk/app-release.apk`. Готовый Windows-дистрибутив — в `build/windows/x64/runner/Release/`; запускать нужно файл `confluence_kb.exe` вместе со всеми файлами этой папки.

## Автоматические сборки

Workflow `.github/workflows/build.yml` запускается при каждом push и вручную из вкладки **Actions** GitHub. Он:

1. создаёт воспроизводимые Flutter-платформы;
2. запускает тесты и анализ;
3. публикует артефакты `confluence-kb-apk` и `confluence-kb-windows`.

В артефакте Windows находится ZIP со всем содержимым Release-папки, включая EXE и необходимые DLL. В артефакте Android — подписанный для установки release APK. По умолчанию APK подписан debug-ключом Flutter, что подходит для внутренней установки. Для публикации в Google Play замените signing configuration на ваш release keystore и храните его в GitHub Secrets.

## Безопасность и данные

- Пароль не передаётся в URL и не записывается в базу. Он хранится в системном защищённом хранилище.
- Не добавляйте пароль, `key.properties` или keystore в Git.
- Отключение проверки TLS намеренно не реализовано. Если внутренний сертификат не доверен устройству, установите корневой сертификат организации.
- В кэше остаётся только контент, доступный введённой учётной записи. При успешной полной синхронизации удалённые на сервере страницы очищаются из локального кэша.
